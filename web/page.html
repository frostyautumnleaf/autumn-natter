    The settings of this program
    Embedding model
    Embedding model The model that counts the words of the sources of retrieval. Nothing is downloaded until the button under it is pressed, and the model is started only while files are being counted or searched.
    Quantization The size of the model file. BF16 is the form the model was published in; a smaller quant takes less room and counts the words a little less finely.
    Vision projector The projector that lets the counting model reach pictures as well as words. It is optional: with none chosen, a picture is searched by its name alone. A projector that is in the folder is used at once.
    CPU only Keep the counting of the sources on the cores of the computer, so that a search never takes the card the answers come from. Turn it off when a folder of files must be counted as fast as the card can manage.
    Batch size How many tokens the counting model takes at once. A larger batch counts a folder of files more quickly and asks for more room.
    Threads How many threads of the computer the counting may use. Zero leaves the choice to llama.cpp.
    Ask length The context the counting server is given, in tokens. One piece of a source is about 900 characters, so the default is far more than any one ask needs.
    State Nothing of the embedding model has been read yet.
    Folder in use Where the files of the embedding model are kept, beside the models of the chats.
    Download What is chosen above and is not in the folder yet is fetched from the repository of the model. A download may be left and come back to, and the files already there are not fetched again.
    Folders
    Data directory in use Where Autumn Natter stores the settings, the chats and the repository data, for this run of the program.
    Other data directory Another place for the settings, the chats, the logs and the records. Leave it empty to keep using the directory above. The folder must already exist; nothing is moved from the old location.
    Context folder in use Where the contexts the model has processed are read from and written to, for this run of the program.
    Context folder Where the processed contexts are kept, and read back instead of rebuilding the chat. Leave it empty for the contexts directory inside the data directory. Contexts in the old location are not read.
    llama.cpp folder The directory that contains llama-server. The program starts that file for every answer.
    Models folder The folder the model files are read from.
    Repositories folder The directory that holds the repositories. Leave it empty to use the default location.
    Repositories
    New repository Create a directory for one project. A chat in a repository runs its terminal commands in that directory.
    Open repository Choose the repository the chats of this window belong to. The directory on disk is named name_id.
    Sandbox
    Network
    Port The port the browser page listens on.
    Share on the network The page can then be opened from other computers on the same network.
    Appearance
    Theme The colours the page is drawn in. Light is the pale ground of the program, Dark the warm near-black, Silver and Corporate the two neutral ladders, Neon a blue-black with lit hairlines, and Glass a translucent material raised above the page. The theme changes at once.
    Pixel-art look Draw the theme in pixel-art form: no rounded corner, no blur, every shadow a flat block, and the text in a fixed-width font. The colours are the colours of the theme, so each theme has a standard look and a pixel-art one. The look changes at once.
    Chatting
    Collapse thinking while it arrives A thinking block shows only its header while the model is thinking. Turn this off to read the thoughts as they arrive. Clicking the header of a block opens or closes that block.
    Thinking panels grow with their words A thinking panel holds all of the thinking and the chat scrolls to show it. Turn this off to keep every thinking panel at a fixed height with a scrollbar of its own.
    Tool blocks inside the thinking panel A tool the model calls while thinking is shown inside the thinking panel that led to it, so the thinking and its tool read as one block. Turn this off to keep the tool block below the thinking panel, as before.
    Collapse a command while it runs A tool block shows only its header while its command runs. Clicking the header of a block opens or closes that block.
    Colour code blocks Text in a code block is coloured by token type: comment, keyword, string, number. Turn this off to show a block in one colour.
    Bold words in the chat Text between two pairs of asterisks is drawn in bold. Turn this off to show the markers as plain text.
    Colour text the model requests The model can colour a few words of its answer: green, light green, red or light red. Turn this off to read the answer with no colour. The markers stay in the conversation that goes back to the model, and the model is informed nothing about the colours.
    Show the work How the work of the model is presented. The plain way shows the thinking in its panels and every call the model made in a block of its own. The compact way hides all of that: one block is one answer, its header reports what the model is doing, and a summary of the work is written inside it by the model. The settings below that lay the panels out have no effect while the compact way is on.
    Seamless chat The panels of the thinking and of the calls are drawn on the chat itself: no background of their own, no border, and no coloured rule down the left edge of a thinking block. The marker that opens a panel then sits beside its heading, instead of at the far right of it: with nothing drawn around a panel, the far right is a long way from the text the marker belongs to.
    Ask a silence over When the model stops by itself without writing a word, a command or an error, the same ask is sent again this many times before the chat reports the model gave no answer. A model that thought a while and then stopped very nearly always goes on when asked again. 0 leaves a silence alone.
    times
    Chapters the model marked The start of a new part of the chat is read from the headings the model writes, and the parts appear on a line at the left of the chat. Clicking one scrolls there. Turn this off to hide the line; the model is then told nothing of chapters either.
    Commands in one answer How many terminal commands the model may run in one answer. -1 means no limit, so the model may run as many commands as it wants. A chapter is not a command and does not use this limit.
    commands, -1 for no limit
    Steps in one answer How many turns of the model one answer may take. Each command is followed by another turn, so a long task needs space here. -1 means no limit: the answer ends only when the model stops by itself.
    turns, -1 for no limit
    Time for one tool call How long a call of a tool is given to come back within. A call that is still running when its time is gone is stopped, and the model is told that it ran out of time; everything the call had given by then still goes back to it. While a call runs, its block offers a mark to stop it and a mark to give it five minutes more. 0 gives a call no time at all, so it may run as long as it likes.
    seconds, 0 for no limit
    A long paste becomes a file When a paste into the chat composer is longer than this, the text is attached to the message as a file instead of being written in the box. The least is 100.
    characters
    Width of the chat How wide the column of the chat may be. 780 pixels is the width the chat always had, and it is the least. The chat never grows past 80 per cent of the width of the window, and it keeps clear of the chapter timeline, the summarisation timeline and the arrows of the chat.
    pixels
    Carry a sent message into the chat Your message leaves the composer as a small card, moves across the chat and unfolds into the message itself. The message is sent at once either way: this only changes how it appears. Turn this off to put the message in the chat the moment you send it. A system that requests reduced motion gets none of this.
    A question of the model waits How long the model waits for your answer to a question before it continues without one and is informed that you did not reply. Questions of this type are the ordinary ones: the model could go on, but would rather ask.
    seconds
    A weighty question waits How long the model waits for a question it flagged as one it cannot continue without (a secret or token that was never given, a choice only you can make). 0 means it waits until you answer, which is what such a question requests.
    seconds, 0 for as long as it takes
    Send the date and time at the start of a chat The program reports the model the date and time of this computer once, in a system message at the start of the conversation, and reports that it is the latest. The line is written when the chat begins and stays as it was for the rest of the chat: a header that moved with the clock would make the model reprocess the whole context on every turn, whatever prompt caching reports. The model can then answer questions about today. The line goes to the model only. It is not shown in the chat.
    Keep a chat's saved context The model only holds a conversation while it is loaded in a slot. Turn this on to save the processed context to a file when the model is freed for another chat or the program is closed. The chat then resumes where it left off instead of being processed from the beginning. Nothing you see in the chat is stored twice, and the files can be deleted at any time: a chat that returns without its file is simply processed again, and the result is the same.
    Compress saved context files Write the saved context files in a compressed form, which takes up much less disk space for a small cost in time. Files already saved in either form are read as they are, so the setting can be changed at any point. Turning it off leaves the compressed files where they are and writes new files in the plain form. Off by default.
    Compaction
    Compaction How the context is rebuilt when it fills up. The handoff summary asks the model, without asking you anything, for a summary of the conversation when the context nears its end. The messages before that summary are then left out of what is sent back to the model, so a chat can go on for ever. The first message you sent is always kept, and the summary follows it. Nothing is removed from the chat you see.
    Start a summarisation Summarise either when the conversation uses a given fraction of the context window of the model, or when the space left falls below a number of tokens.
    Share of the context The conversation is summarised when it uses this share of the context window of the model.
    per cent
    Space to keep free The conversation is summarised when the space left is this small or smaller, so the next answer has space to be written.
    tokens
    Handoff prompt What the model is set to write when a summary is requested. Leave it empty to use the prompt of the program. At most 4096 characters.
    Short handoff prompt The first summary is given all the space left and may be as long as it likes. When it fills that space and stops in the middle, the model is asked again with this text, which requests a very short summary. Leave it empty to use the prompt of the program. At most 4096 characters.
    Summarisation timeline A vertical line at the right of the chat with one node for every summarisation. A node shows which summarisation it is and part of its text; clicking one scrolls there.
    Message timeline A vertical line hard against the right edge of the chat, with one short dash for every message you sent. A dash says which message it is and when you sent it, and shows part of it and what was attached to it; clicking one scrolls there. Turn this off to hide the line.
    Background of the chat What falls behind the text of the chat. Nothing falls by default. Autumn leaves are the leaf of the program icon, in a colour just off the background of the chat - a shade darker on a pale theme, a shade lighter on a dark one - turning as they come down. They fall only while a model is answering, and stop when it stops. Rain falls in squares of colour, one tone off the background of the chat, and goes on whether a model is answering or not.
    Rain splashes Where the rain meets the chat composer box, or a block of the chat, it breaks into a splash of squares - over the top edge of the block it hits, in a place drawn anew each time, so no two splashes are as well. The splash is only ever on the screen: nothing is heard, and nothing of a block moves with it. Turn this off to have the rain fall past the blocks untouched.
    Digits under the cursor While the cursor rests in the chat, a soft round aura about it uncovers a field of random digits in the background: rows and columns of numbers in the colour of the leaf mark, coming in and going out with no edge to them. The aura breathes in and out while the cursor stands still. This is off until you turn it on. A system that asks for little movement gets none of this.
    Grid background The background of the chat is a faint grid of hairlines in the colour of the theme, instead of a solid colour. Now and then one line of the grid swings slowly into a wave and comes back to straight again, at a place and a time drawn at random, so no two times at a chat show the same movement. Turn this off to have the plain solid colour back. The pixel-art form of a theme has a background of its own and keeps it.
    Custom system prompt
    System prompt Your own text, placed at the start of every chat, before the first message. The model reads it as the rules it must answer by: how long an answer is, what tone it keeps, and what it never does. The text of the program, which tells the model about the tools and the chat, still remains, and your text goes in front of it. Leave it empty for no prompt of your own. At most 8000 characters.
    Pre-written prompts Prompts written in advance, which you can insert with a marker instead of typing your own. An inserted prompt goes before the text you wrote, in the order of this table. The View button shows all of a prompt.
    Copy and presets
    These settings as words All of this tab in one piece of text, so that it can be put on another model, kept in a file, or sent to someone else. Copy takes what is in the fields now, text not yet saved included, and puts it in the box below and on the clipboard. Paste reads such text and puts it into the fields. A setting the text reports nothing about is where it was. Nothing reaches the model until you press Save.
    Preset A set of the settings you want to keep, under a name of your own. A preset belongs to no model, because it is one way of configuring a model rather than the settings of one model: long answers on a big graphics card, or a chat that never swaps the context. Presets are kept with the settings of the program, so every model can reach them.
    Name of the preset The name the preset is kept under. Choosing a preset above writes its name here, so saving again overwrites that preset. Up to 60 characters.
    Keep, load, throw away Save takes the settings that are in the fields of this tab. Load puts a preset into the fields, and Delete removes a preset from the list. Neither changes a model until you press Save.
    Sizing
    Context size How much of the conversation the model keeps in mind at once. More uses more memory.
    tokens
    KV cache type Lower precision uses less memory for the conversation, and makes answers slightly worse.
    Model load mode Loads the model into memory, from disk, or both.
    Advanced
    Checkpoints The greatest number of conversation checkpoints the server keeps, so it can return to one and reuse the work done before it. 0 turns checkpoints off.
    0 for off
    Cache ram The greatest memory the KV cache may use, in mebibytes. 0 turns the cache off, and -1 removes the limit.
    MiB, -1 for no limit
    Cache prompt The server reuses the work done on text already sent on the next turn. Turn this off to recompute it on every turn.
    No context shift When the conversation overflows the context, the server drops the old text and keeps going. Turn this on to stop that, so the answer stops at the edge of the context. Useful when coding.
    Sampling
    Temperature How much the next token is chosen at random. A low value is more focused, and a high value more varied.
    0 to 5
    Top p The model chooses from the tokens that carry this share of the probability. 1 keeps every token.
    0 to 1
    Top k The model chooses from the k most likely tokens. 0 keeps every token.
    words
    Min p A token less likely than this fraction of the top token is dropped. 0 keeps every token.
    0 to 1
    Advanced
    Repetition penalty A token that appeared before is generated again less often. 1 turns the penalty off.
    1 for off
    Presence penalty Every token that appeared before is penalised once. 0 turns the penalty off.
    0 for off
    Max tokens The most tokens one answer may produce. -1 means no limit.
    -1 for no limit
    Seed The start of the random choice. -1 draws a new value on every start. A fixed seed gives the same answer for the same input.
    -1 for random
    Speculative decoding
    Speculation type The model may guess a few tokens ahead and then verify them. "ngram-mod + MTP" runs both at once: the drafts come from the context by n-gram and from the MTP header of the model.
    Draft model The file of the small model that drafts tokens ahead. Leave it empty to draft from the context. With MTP requested and nothing set here, the MTP header is taken from the MTP file beside the model file.
    Draft tokens How many tokens the model drafts ahead before it verifies them.
    words
    Ngram look-up length For ngram-mod: how long a run of tokens to search for in the context before drafting from it. 0 keeps the server default (24).
    0 for the server value
    Ngram most words For ngram-mod: the most tokens it may draft at once. 0 keeps the server default (64).
    0 for the server value
    Ngram least words For ngram-mod: the least number of tokens it needs to draft at all. 0 keeps the server default (48).
    0 for the server value
    Working
    Parallel chats How many conversations the server may serve at the same time.
    chats
    Batch size The size of one batch of tokens handed to the model.
    words
    Micro-batch size The part of a batch a graphics card works on at once.
    words
    Read images Read the images of a chat, when the model can look at them.
    Advanced
    Image minimum tokens The least tokens one image may use, for a model that can look at images. 0 keeps the value stored in the model file.
    0 for the model value
    Image maximum tokens The most tokens one image may use, for a model that can look at images. 0 keeps the value stored in the model file.
    0 for the model value
    Offload vision to CPU The projector that reads images runs on the graphics card by default. Turn this on to run it on the CPU and leave the card free for the model.
    Thinking
    Thinking budget How many tokens a model may spend on thinking before it answers. -1 leaves it to the model.
    words
    Message when the budget is removed The text the server appends when the model has used all the thinking space.
    Cards
    Advanced
    Tensor parallelism Split the model across every card that is on. Off keeps the model on the first card only.
    Graphics cards
    VRAM budget How much of the graphics cards the model may use. What is left over is kept for the server and the conversation. The fit of the model into the cards is always requested, with the context size you set, and the space left over on a card never falls below 256 MiB.
    90%
    Template
    Chat template Leave it empty to use the template inside the model file.
    Extra arguments
    Extra arguments Arguments given to llama-server as they are now. They take priority over the fields above.
    Default arguments Send the arguments this program builds from the fields above. Off sends only the model, its name, the address and the port. Use Off for a server of another build that knows none of these arguments. Put the arguments that server needs into the field above, because they are sent last and win. With Off, nothing else of this tab is requested, and the chats are not kept.
    Command line

    Add a server
    
        
    Name
          The name shown in the badge menu and in the tool blocks of the chat for this server.
          
    
        
    Icon
          One marker for this server, so its entries are distinguished in the menu.
          
    
        
    Kind
          A program on this computer, a server on the network, or Python code that the program runs.
          
    
        
    Command
          The whole command that starts the server, quotes included. The server conversations over its standard input and its standard output.
          
    
        
    Address
          The address of the server. It is reached over Streamable HTTP.
          
    
        
    Python code
          Write a function, and marker the ones the model may use with @tool. The names and types of its arguments become the parameters of the tool, and its doc string becomes its description, on one line. Nothing beyond the Python standard library is needed. A whole MCP server of your own is run as it is now. An empty field of this type is filled with an example of its own, and the rules a server of this type has to keep are at the header of it. Give those rules, with the example, to an AI, and it can write a server that works here.
          
    
        
    In the menu
          Whether this server is in the drop-down of the MCP badge. A server hidden from the menu is stored here all the same.
          
    
        
    Save this server
          The server is saved, and its tools are read. Nothing else of the settings changes.

    Logs
    
        
    Which log
          llama.cpp writes the log of the server. The program writes a log of its own work: the size of the context, the handoff summary and the context meter. Both are in the same directory, and the ten newest of each are kept.
          
    
              
              
            
    
        
    Log
          One log for every start of llama-server, or one for every run of the program. The ten newest logs of the chosen type are kept and older ones are deleted. The log this run of the program is writing is flagged Now and is selected by itself.
          
    
        
    Update
          How often the log is reloaded while this tab is open. Manual reloads nothing until Refresh is pressed; for the other two that button is greyed out, because there is nothing to press.
          
    
        
    Follow the end
          Keep the view at the last line while the log grows. Scrolling up turns this off, as in the chat.
          
    

        
    Search this log
          The lines that contain the text are shown on their own, each with its line number, and the two step buttons move between them. An empty field shows the end of the log. The search checks the part of the log that was read.
