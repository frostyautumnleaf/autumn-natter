Folders
Data directory Where Autumn Natter stores the settings, the chats and the repository data.

Sandbox
Network
Port The port the browser page listens on.
Share on the network The page can then be opened from other computers on the same network.
Appearance
Dark mode Use the dark colour scheme instead of the light one. It changes at once.
Chatting
Collapse thinking while it arrives A thinking block shows only its head while the model is thinking. Turn this off to read the thoughts as they arrive. Clicking the head of a block opens or closes that block.
Thinking panels grow with their words A thinking panel holds all of the thoughts and the chat moves to read them. Turn this off to keep every thinking panel at a fixed height with a rail of its own.
Tool blocks inside the thinking panel A tool the model calls while thinking stands inside the thinking panel that led to it, so the thought and its tool read as one part. Turn this off to keep the tool block under the thinking panel, as it was.
Collapse a command while it runs A tool block shows only its head while its command runs. Clicking the head of a block opens or closes that block.
Colour code blocks Text in a code block is coloured by kind: comment, keyword, string, number. Turn this off to show a block in one colour.
Bold words in the chat A word held between two marks of boldness is written in the heavier shape of the letters. Turn this off to read the marks as part of the words themselves.
Chapter markers The model may mark where a new part of the chat begins. The markers appear on a line at the left of the chat, and clicking one scrolls there. Turn this off to hide the line; the model is then not offered the tool.
Commands in one answer How many terminal commands the model may run in one answer. -1 means no limit, so the model may run as many commands as it wants. A chapter marker is not a command and does not use this limit.
commands, -1 for no limit
Steps in one answer How many turns of the model one answer may take. Each command is followed by another turn, so a long task needs room here. -1 means no limit: the answer ends only when the model stops by itself.
turns, -1 for no limit
A long paste becomes a file When a paste into the chat box is longer than this, the text is attached to the message as a file instead of being written in the box. The least is 100.
characters
Width of the chat How wide the column of the chat may be. 780 pixels is the width the chat always had, and it is the least. The chat never grows past 80 per cent of the width of the window, and it keeps clear of the line of the chapters, the line of the summarisations and the arrows of the chat.
pixels
A question of the model waits How long the model waits for you to answer a question it put to you before it goes on without an answer and is told that you did not reply. Questions of this kind are the ordinary ones: the model could go on, but would rather ask.
seconds
A weighty question waits How long the model waits for a question it marked as one it cannot go on without — a token that was never given, a choice only you can make. 0 means it waits until you answer, which is what such a question asks for.
seconds, 0 for as long as it takes
Send the date and time at the start of a chat The program tells the model the date and time of this machine once, in a system message at the start of the conversation, and says that it is the latest. The line is written when the chat begins and stands as it was for the rest of the chat: a head of the talk that moved with the clock would make the model read the whole talk over again on every turn, whatever prompt caching says. The model can then answer questions about today. The line goes to the model only. It is not shown in the chat.
Compaction
Compaction How the context is made again when it fills up. The handoff summary asks the model, without asking you anything, for a summary of the conversation when the context nears its end. The messages before that summary are then left out of what is sent back to the model, so a chat can go on for ever. The first message you sent is always kept, and the summary follows it. Nothing is removed from the chat you see.
Start a summarisation Either when the conversation uses a given share of the context window of the model, or when the space left has fallen under a number of tokens.
Share of the context The conversation is summarised when it uses this share of the context window of the model.
per cent
Space to keep free The conversation is summarised when the space left is this small or smaller, so the next answer has room to be written.
tokens
Handoff prompt What the model is told to write when a summary is asked for. Leave it empty to use the prompt of the program. At most 4096 characters.
Short handoff prompt The first summary is given all the space left and may be as long as it likes. When it fills that space and stops in the middle, the model is asked again with these words, which ask for a very short summary. Leave it empty to use the prompt of the program. At most 4096 characters.
Summarisation timeline A vertical line at the right of the chat with one node for every summarisation. A node says which summarisation it is and shows part of it; clicking one scrolls there.
Sizing
Context size How much of the conversation the model keeps in mind at once. More uses more memory.
tokens
KV cache type Lower precision uses less memory for the conversation, and makes answers slightly worse.
Model load mode Loads the model into memory, from disk, or both.
Advanced
Checkpoints The most points of the conversation the server saves, so it can return to one and reuse the work done before it. 0 turns checkpoints off.
0 for off
Cache ram The most memory the conversation may use, in mebibytes. 0 turns the cache off, and -1 removes the limit.
MiB, -1 for no limit
Cache prompt The server keeps the work done on text already sent and reuses it on the next turn. Turn this off to pay that work again on every turn.
No context shift When the conversation overflows the context, the server drops the old text and keeps going. Turn this on to stop that, so the answer stops at the edge of the context. Useful when coding.
Sampling
Temperature How freely the model chooses from the words it can say. A low value is safer, and a high value is looser.
0 to 5
Top p The model chooses from the words that hold this share of the probability. 1 keeps every word.
0 to 1
Top k The model chooses from the k most likely words. 0 keeps every word.
words
Min p A word less likely than this share of the top word is dropped. 0 keeps every word.
0 to 1
Advanced
Repetition penalty Words that appeared before are made less likely. 1 turns the penalty off.
1 for off
Presence penalty Every word that appeared before is made less likely once. 0 turns the penalty off.
0 for off
Max tokens The most tokens one answer may produce. -1 means no limit.
-1 for no limit
Seed The start of the random choice. -1 draws a new one on every start. A fixed seed gives the same answer for the same text.
-1 for random
Speculative decoding
Speculation type The model may guess a few words ahead and then check them.
Draft model The file of the small model that guesses words ahead. Leave it empty to guess from the chat.
Draft tokens How many words the model tries ahead before it checks them.
words

Parallel chats How many conversations the server may serve at the same time.
chats
Batch size The size of one batch of words handed to the model.
words

Image minimum tokens The least tokens one image may use, for a model that can look at images. 0 keeps the value stored in the model file.

0 for the model value

Add a server

        
Name
          The name the menu of the badge and the blocks of the chat show beside the tools of this server.
          

        
Icon
          One mark for this server, so its lines are known apart in the menu.
          

        
Kind
          A program of this machine, a server on the network, or words of Python that the program runs.
          

        
Command
          The whole line that starts the server, quotes and all. The server speaks over its standard input and its standard output.
          

        
Address
          The address of the server. It is spoken to over Streamable HTTP.
          

        
Python code
          Write a function, and put @tool over the ones the model may use. The names and the types of its arguments become the parts of the tool, and its doc string becomes the description of it, in one line. Nothing beyond the library that stands with Python is needed. A whole MCP server of your own is run as it stands. An empty field of this kind is filled with an example of its own, and the rules a server of this kind has to keep stand at the head of it. Give those rules, with the example, to an AI, and it can write a server that works here.
          

        
In the menu
          Whether this server stands in the drop-down of the MCP badge. A server left out of the menu is kept here all the same.
          

        
Save this server
          The server is kept, and its tools are read. Nothing else of the settings moves.
